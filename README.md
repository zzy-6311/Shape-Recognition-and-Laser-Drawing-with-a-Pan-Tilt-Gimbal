# diansai-xuanba — 二维云台激光绘图系统

用**二维云台 + 激光笔**在画板上"画"出图形，并用**摄像头**识别 A4 纸上的图案后按原尺寸复现到画板上。

- 基本部分：画点回程、正方形、等边三角形、梯形
- 发挥部分：转 180° 用摄像头识别目标图形 → 转到画板方位 → 按识别到的尺寸画图，支持画板在固定方位或 360° 扫描自动寻找

> ⚠️ **请先读第 7 节「风险说明与已知问题」**。仓库里附带的 `calibration.json` 标定数据**几乎肯定不能直接用于主程序**，直接跑会得到错误的距离和图形尺寸。

## 1. 赛题要求

原始题目见 [`other/题目要求.txt`](other/题目要求.txt)，摘要：

**基本要求**（按下一键启动后）

| 项 | 内容 | 误差要求 |
|---|---|---|
| 基本1 | 先在画板上画一个点，控制画笔转一圈后能再次画在原来的点上 | < 2cm |
| 基本2 | 在画板上画出一个正方形 | — |
| 基本3 | 画出边长 6cm 的等边三角形 | < 2cm |
| 基本4 | 画出上底 15cm、下底 20cm、高 15cm 的梯形 | < 2cm |

**发挥部分**：识别目标物区域中的图片物体，并在画板上绘制出来。画板依次位于 **90° / 180° / 270°** 线上，最后要求目标物放置面与画板可能位于圆周上的任意位置。误差要求 2cm（发挥3 为 1cm）。

## 2. 系统构成

### 2.1 硬件清单

| 部件 | 说明 |
|---|---|
| 主控 | 树莓派（Raspberry Pi OS + Python 3） |
| 云台电机 ×2 | JC 系列步进电机驱动器，**Modbus-RTU 串口**控制 |
| 激光笔 | 经继电器控制，接 GPIO |
| 摄像头 | USB 摄像头 |
| 数码管 | 7 段共阳极，显示当前模式号 |
| 按钮 ×2 | 一个切换模式，一个开始执行 |

### 2.2 接线（BCM 编号）

| 功能 | GPIO | 备注 |
|---|---|---|
| 激光继电器 | **15** | 高电平 = 激光亮 |
| 数码管 a/b/c/d/e/f/g | **9 / 11 / 0 / 5 / 6 / 13 / 19** | 共阳极，**低电平点亮** |
| 模式切换按钮 | **21** | 接 GND，启用内部上拉 |
| 开始按钮 | **20** | 接 GND，启用内部上拉 |
| Pan（航偏）电机 | `/dev/ttyACM0` | 115200, 8N1，Modbus 地址 `0x01` |
| Tilt（俯仰）电机 | `/dev/ttyACM1` | 115200, 8N1，Modbus 地址 `0x01` |

电机串口协议（0x03 / 0x06 / 0x10 功能码、PVT / PV 指令、CRC16）见 [`other/云台串口通信说明.txt`](other/云台串口通信说明.txt)。

### 2.3 坐标与角度换算

激光发射点到画板的垂直距离为 `DISTANCE_MM`（默认 900mm）。画板上一点 `(x, y)` 对应的云台角度：

```
pan  = atan2(x, DISTANCE_MM)
tilt = atan2(y, DISTANCE_MM + TILT_OFFSET_MM)
```

`TILT_OFFSET_MM`（默认 10mm）是俯仰旋转中心到激光头的物理偏移，**需实测标定**。

## 3. 文件说明

| 文件 | 角色 |
|---|---|
| **`work-pi.py`** | **主程序**。串口控制云台 + GPIO 控制激光/数码管/按钮 + 内嵌视觉识别 + 模式状态机。比赛时跑的就是它。 |
| `my-cv.py` | **视觉算法母本** + 摄像头实时调试。`work-pi.py` 里的检测函数是从它复制后改造的。 |
| `my-cv-one.py` | **单张图片离线调参工具**。不接摄像头，读 `sucai/9.jpg`，改一次参数看一次结果，适合反复调视觉参数。 |
| `calibrate.py` | **测距标定工具**。产出 `calibration.json` 的 K1/K2。 |
| `other/云台串口通信说明.txt` | 电机驱动器协议手册（实现串口通信的依据）。 |
| `other/题目要求.txt` | 赛题原文。 |
| `sucai/1.jpg … 12.jpg` | 素材照片，供 `my-cv-one.py` 离线调参使用。 |
| `calibration.json` | 测距标定结果（**见风险 R1**）。 |
| `zero_offset.json` | 电机零点偏移，运行标定模式后生成；**本仓库不包含**（运行时产生）。 |

### 3.1 调用与数据流

```
other/云台串口通信说明.txt
      │ 实现 Modbus 协议
      ▼
work-pi.py ─┬─ crc16_modbus / send_modbus / pvt_cmd / pv_cmd ─串口─▶ 云台电机 ×2
            ├─ gpiozero ─▶ 激光继电器 + 数码管 + 按钮
            ├─ load_calib() ──读──▶ calibration.json ◀──写── calibrate.py / 模式12
            ├─ load_zero()/save_zero() ─读写─▶ zero_offset.json ◀── 模式11
            └─ 内嵌视觉（detect_a4 / find_shapes_in_roi / classify_shape / measure_shape）
                                     ▲
                                     ║ 代码复制（不是 import）
                                     ║
                               my-cv.py（母本）
                                     │
                               my-cv-one.py（复制后改为读 sucai/9.jpg）
```

**注意：`work-pi.py` 不 `import my-cv.py`。** 它把视觉函数整份抄进自己文件里，因为需要把返回类型从"给人看的字符串"（`"side=80mm"`）改成"给机器算的字典"（`{"side": 80.0}`），才能喂给绘图代码。所以**改视觉算法时两边都要同步改**，否则行为会不一致。

### 3.2 视觉识别流程

1. **找 A4 纸**（`detect_a4`）
   灰度 → 高斯模糊 → 按亮度阈值二值化（白纸=白）→ `RETR_TREE` 取偶数层轮廓（排除纸内图案形成的"洞"）→ 四边形逼近 + 四角直角校验 + 宽高比校验 → 得到纸张轮廓与 ROI
2. **识别纸内图形**（`find_shapes_in_roi`）
   ROI 内自适应阈值（失败回退 OTSU）→ 中心掩膜排除纸边框 → 逐个轮廓多边形逼近 → 按顶点数/圆形度分类为 triangle / square / trapezoid / circle → 用 `mm_per_px` 换算实际尺寸
3. **画图**（`shape_to_points` → `xy_to_angle` → 电机指令）

```bash
git clone https://github.com/zzy-6311/diansai-xuanba.git
```

## 5. 使用方法

推荐顺序：**先标定 → 再调视觉 → 最后跑主程序**。

### 5.1 第一步：测距标定

距离公式（全项目统一）：

```
D = (K1 / w_pixel + K2 / h_pixel) / 2
```

其中 `w_pixel`/`h_pixel` 是检测到的白色区域的像素宽高，`K = 实际距离 × 像素尺寸`。

**方式 A（推荐）：用主程序的模式 12 标定**

这样摄像头编号、分辨率、检测区域都和实际运行时完全一致，K 值天然可用。

1. `python3 work-pi.py`
2. 按模式切换按钮，直到数码管显示 **`b`**（= 模式 12）
3. 按开始按钮，进入摄像头调试
4. 把 A4 纸放在画板位置，量出纸面到摄像头的实际距离 `D`（mm）
5. 画面里会显示 `W:xxx H:xxx`（像素尺寸），按 **C** 键
6. 输入实际距离 `D`，然后选择 **覆盖(o)** 或 **平均(a)**
7. 按 **Q** 退出，`calibration.json` 已写入

**方式 B：用 `calibrate.py` 独立标定**

1. 把 A4 纸正对摄像头放在已知距离处
2. `python3 calibrate.py`
3. 按 **S**，输入当前实际距离（mm），记录一组
4. 换几个不同距离重复第 3 步（K 会取平均，右下角表格显示历史与误差）
5. 按 **Q** 退出（实时保存）；按 **R** 清除全部记录重来

> ⚠️ 方式 B 的摄像头编号（`CAMERA_ID=1 / 640×480`）与主程序（`CAMERA_ID=0 / 1080×640`）**不同**，且检测的是暗色轮廓而非白色纸面。**除非你把 `calibrate.py` 的参数改成与主程序一致，否则不要用方式 B 的结果跑主程序。** 详见风险 **R1**。

### 5.2 第二步：视觉参数调优

全部视觉参数集中在各文件顶部的"参数区"，并有中文注释说明每个值的含义和调整方向。

**离线调参（推荐，快且可复现）**

```bash
python3 my-cv-one.py
```

- 读 `sucai/9.jpg`（改 `IMAGE_NAME` 可换图）
- 会打印 `[调试]` 信息，告诉你"最大轮廓为什么被跳过"
- 弹出 `A4`、`ROI_1`、`shape_binary` 等窗口，按任意键关闭

**实时调参**

```bash
python3 my-cv.py
```

- 打开摄像头实时检测，结果打印在终端（画面压缩后字看不清），窗口里画出 A4 外框
- 按 **Q** 退出

**主程序内调试**：模式 12（数码管 `b`）就是同一个检测流程的实时版本。

调参要点：

| 现象 | 调整 |
|---|---|
| 找不到 A4 纸 | 调低 `A4_BRIGHT_THRESH`（阈值太高只认纯白）；弱光下调到 130 左右 |
| 把灰色背景当成纸 | 调高 `A4_BRIGHT_THRESH` |
| 远处纸太小识别不到 | 调小 `A4_MIN_AREA` |
| 梯形被误判成正方形 | 调小 `SHAPE_ANGLE_TOLERANCE`（直角容差） |
| 三角形/梯形被误判成圆 | 调高 `SHAPE_CIRCULARITY_THRESHOLD` |
| 纸面反光、噪点多 | 把高斯核从 `(3,3)` 调到 `(5,5)` |

改完 `my-cv-one.py` 里的算法后，**记得同步到 `my-cv.py` 和 `work-pi.py`**。

### 5.3 第三步：跑主程序

```bash
python3 work-pi.py
```

启动后：

1. 自动加载 `zero_offset.json`（若无则用出厂物理零点）
2. 初始化数码管 + 按钮 + 激光
3. 打开两个电机串口并归零
4. 进入**模式选择循环**：
   - 按**模式按钮** → 数码管数字跳一个
   - 按**开始按钮** → 执行当前模式
   - `Ctrl+C` 退出

#### 模式对照表

数码管显示 `A` = 11，`b` = 12。

| 模式 | 名称 | 动作 | 需要云台 |
|---|---|---|---|
| 1 | 基本1 回程精度 | 归零 → 点亮激光 1s（记起点）→ 关激光 → 转 -360° → 点亮 1s（记回程点）→ 关激光 → 归零 | ✅ |
| 2 | 基本2 正方形 | 闭环对准画板 → 画 80mm 正方形 | ✅ |
| 3 | 基本3 等边三角形 | 闭环对准画板 → 画 60mm 等边三角形 | ✅ |
| 4 | 基本4 梯形 | 闭环对准画板 → 画 100/60/80mm 梯形（旋转 90° 竖画） | ✅ |
| 5 | 发挥1 | 转 180° 识别目标 → 回 0° → 测距 → 按识别尺寸画图 | ✅ |
| 6 | 发挥2 | 画板在 **270°** 方位 | ✅ |
| 7 | 发挥3 | 画板在 **90°** 方位 | ✅ |
| 8 | 发挥4 | 360° 扫描找画板与素材 → 闭环对准 → 画图 | ✅ |
| 9 | 空模式 | 占位，不执行任何动作 | ❌ |
| 11 | 标定（`A`） | 手动微调云台并保存零点偏移 | ✅ |
| 12 | 摄像头调试（`b`） | 实时看 A4 检测与图形识别，C 键现场算 K 值 | ❌ |

> 模式 5/6/7 的方位与赛题要求不一致，见风险 **R3**。

#### 模式 11：零点标定

进入后按提示输入命令：

| 键 | 作用 |
|---|---|
| `W` / `S` | Tilt 粗调 ∓1° |
| `A` / `D` | Pan 粗调 ∓1° |
| `I` / `K` | Tilt 微调 ∓0.1° |
| `J` / `L` | Pan 微调 ∓0.1° |
| `R` | 归零 |
| `P` | 读取当前位置 |
| `C` | **保存零点偏移并退出**（写入 `zero_offset.json`） |
| `Q` | 不保存退出 |

标定目标：让激光在 `pan=0, tilt=0` 时准确落在画板原点。`zero_offset.json` 删掉即恢复出厂物理零点。

#### 模式 8（发挥4）的扫描逻辑

- 每 `SCAN_STEP_DEG`（默认 30°）转一步，共 12 步扫一圈
- 每步等 `SCAN_DELAY_S` 稳定后拍照，识别结果做**二次确认**避免单帧误判
- **没有图形**的纸 = 画板；**有图形**的纸 = 素材
- 两者角度差小于 `MIN_SCAN_SEPARATION_DEG`（默认 30°）时判定为同一张纸的误识别
- 找到画板后进入 `servo_to_board` 闭环对准（调 Pan 使纸张中心与画面中心对齐）
- 用 `detect_a4` 测出的实际距离修正图形尺寸：`尺寸 × (DISTANCE_MM / 实测距离)`
- 最后额外加 `SHAPE_DRAW_OFFSET_MM`（默认 10mm，补偿检测外轮廓偏大）

## 7. 风险说明与已知问题

按严重程度排序。**R1 / R2 / R3 会直接导致成绩不达标，请务必处理。**

---

### R1 【高】仓库里的 `calibration.json` 几乎肯定不能用于主程序

**现象**：直接 clone 下来跑主程序，距离和图形尺寸会系统性偏大/偏小。

**证据**：

1. `calibration.json` 里只有 **1 条**记录：

   ```json
   { "K1": 154540.31, "K2": 107502.38,
     "records": [{ "dist": 1000.0, "w_pixel": 154.54, "h_pixel": 107.50 }],
     "count": 1 }
   ```

2. 这条记录暗示的标定区域**宽高比**是 `h/w = 107.50 / 154.54 = 0.696`

3. 而 `work-pi.py` 配置的白色区域宽高比是 `A4_WIDTH_MM / A4_HEIGHT_MM = 170 / 257 = 0.661`

   → 两者相差约 **5%**，说明**标定的不是主程序实际检测的那块区域**

4. 更关键的差异：`calibrate.py` 用 `THRESH_BINARY_INV` 找**暗色**轮廓（即纸张黑框外沿），而 `work-pi.py` 用 `THRESH_BINARY` 找**白色**纸面。黑框外沿与白面内沿的物理尺寸不同（约 210/297mm vs 170/257mm），比值约 1.16 → **距离可能偏差 15% 以上**

5. 摄像头配置也不同：`calibrate.py` 用 `CAMERA_ID=1 / 640×480`，`work-pi.py` 用 `CAMERA_ID=0 / 1080×640`

**影响**：`D = (K1/w + K2/h)/2` 直接算错 → `scale_params()` 按错误距离缩放图形 → **画出来的图形尺寸不对**，而赛题要求误差 < 2cm。

**处理**：

- ✅ **用 `work-pi.py` 的模式 12 重新标定**（同摄像头、同分辨率、同检测区域，K 值天然一致）
- ✅ 标定后删掉仓库这份 `calibration.json`（或把它加进 `.gitignore`）
- ⚠️ 若坚持用 `calibrate.py`，必须先把它的 `CAMERA_ID`/分辨率/阈值方向改成与主程序一致，并确认标定的是**同一块白色区域**

### R2 【高】标定文件按"当前工作目录"查找，不是按脚本位置

**现象**：从其它目录运行程序时，读不到标定数据，或者 `zero_offset.json` 被写到意料之外的地方。

**原因**：三个文件用的都是裸文件名：

```python
# calibrate.py:66 / my-cv.py:88 / work-pi.py:221
CALIB_FILE = "calibration.json"

# work-pi.py:111
ZERO_FILE = "zero_offset.json"
```

`open("calibration.json")` 相对于**进程的当前工作目录**（CWD），不是脚本所在目录。

**只有 `my-cv-one.py` 做对了**：

```python
img_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "sucai", IMAGE_NAME)
```

**触发场景**：

- 用绝对路径运行：`python G:\...\work-pi.py`
- IDE 里把"工作目录"设成了项目根以外的地方
- systemd / 开机自启脚本没有设置 `WorkingDirectory`
- 在项目目录里建了子目录后进去运行

**处理**（二选一）：

- 简单：**每次运行前先 `cd` 到项目根目录**
- 彻底：把三处改成基于脚本位置，例如

  ```python
  BASE_DIR = os.path.dirname(os.path.abspath(__file__))
  CALIB_FILE = os.path.join(BASE_DIR, "calibration.json")
  ZERO_FILE = os.path.join(BASE_DIR, "zero_offset.json")
  ```

### R3 【高】模式方位与赛题要求不一致

**赛题要求**：发挥(1) 画板在 90° 线、(2) 180° 线、(3) 270° 线。

**代码实际**：

| 模式 | 代码里的方位 | 赛题期望 |
|---|---|---|
| `m5`（发挥1） | `_get_board_dist(sp, st, 0)` → **0°** | 90° |
| `m6`（发挥2） | `draw_angle = 270.0` → **270°** | 180° |
| `m7`（发挥3） | `draw_angle = 90.0` → **90°** | 270° |
| — | **没有画在 180° 的模式** | 180° |

**可能是**：你的物理零位定义与赛题描述不同（比如摄像头朝向与激光朝向差 180°，所以"画板在 0°"对应赛题说的某个角度）。但**在没有实物确认前不能假定它是对的**。

**处理**：

- ✅ 上机前按实际场地布置，逐个核对 `m5`/`m6`/`m7` 里的 `draw_angle`，以及 `m1` 的回程角度
- 如果场地严格按赛题布置，需要改代码或改接线把三个方位对齐

### R4 【中】激光安全

激光笔由云台驱动，**会扫过整个水平 360° 范围和一定的俯仰范围**。

- 直射眼睛可造成**不可逆的视网膜损伤**
- `m1`（回程）会在 0° 位置点亮激光 1 秒；模式 5~8 绘图时会持续点亮
- 模式 8 扫描时云台会带着摄像头（和可能的激光）转动

**必须做到**：

- 佩戴对应波长的**激光防护镜**
- **避免视线与激光光路同高**（蹲下或站远）
- 启动前确认**光路范围内没有人**，尤其不要让孩子或未戴护目镜的人靠近
- 调试时优先用**模拟/日志**确认轨迹，再开激光
- 不要把激光对准反光面（镜面、金属、玻璃）——反射光同样伤眼

### R5 【中】PC 上无法选择模式，连模式 12 也进不去

**原因**（`work-pi.py` 的 `main()`）：

```python
if not _HAVE_UI:
    print("\n[错误] 未检测到数码管/按钮硬件，无法选择模式")
    cleanup(sp, st)
    return
```

而 `init_ui()` 又以 `_HAVE_LASER` 为前置条件：

```python
def init_ui():
    if not _HAVE_LASER:
        print("[UI] gpiozero 不可用，跳过")
        return
```

于是：**没有 gpiozero / 激光初始化失败 → 整个程序直接退出**。

**问题在于**：模式 12（摄像头调试）和模式 11（标定，只用串口）其实**不需要**数码管和按钮。文件头的注释也写着"可以在 PC 上测试"，但实际上做不到。

**影响**：想在 PC 上调摄像头或在无 GPIO 环境下标定，只能改用 `my-cv.py` / `calibrate.py`——但那样标定出的 K 值又不适用于主程序（见 R1），形成死循环。

**处理**：

- 临时：在树莓派上做摄像头调试和标定（推荐）
- 彻底：无 UI 时加一个命令行选模式的回退分支，允许 `--mode 12` 之类的入口

### R6 【中】仓库缺少 `.gitignore`

现在 `git add --dry-run` 看起来是干净的，那是因为 `other/__pycache__` 是个**空目录**——而 **Git 不跟踪空目录**。

但只要在仓库目录里**跑过一次任何脚本**，就会生成 `__pycache__/*.pyc`，之后 `git add .` 就会把它们一起提交。

**这个仓库的源目录已经有过先例**：一个**没有对应源码的孤儿** `xuanba_comp.cpython-311.pyc`（`xuanba_comp.py` 早就删了，缓存文件却留了好几个月）。

**处理**：在仓库根目录新建 `.gitignore`：

```gitignore
# Python 字节码
__pycache__/
*.py[cod]
*$py.class

# 虚拟环境
.venv/
venv/
env/

# 运行时生成的机器相关文件（换机器/换摄像头必须重新标定）
zero_offset.json
# calibration.json      # 取消注释 = 不把标定值提交进仓库（见 R1、R7）

# IDE / 编辑器
.idea/
.vscode/
*.swp
.DS_Store
```

### R7 【中】已提交的 `calibration.json` 会误导使用者

它是**某台设备、某个分辨率、某次实验**下的标定结果，且只有 1 组数据（没有取平均）。

- 别人 clone 下来直接跑 → 距离算错 → 图形尺寸不对
- 你自己换了摄像头/分辨率 → 同样失效

而 `work-pi.py:227` 注释里给的示例是 `D=725mm → K1=246500`，和仓库里的 `154540` 差了 60%，**两个数据互相矛盾**。

**处理**：

- 要么加进 `.gitignore` 不提交
- 要么保留，但在 README（本文档 R1）和 `calibration.json` 附近**显著标注"必须重新标定"**

### R8 【低】串口设备名硬编码为树莓派路径

```python
SERIAL_PORT_PAN  = "/dev/ttyACM0"
SERIAL_PORT_TILT = "/dev/ttyACM1"
```

- Windows 上是 `COMx`，需要改
- Linux 下**设备号会随 USB 插入顺序变化**：先插 Tilt 再插 Pan，两个口就互换了，程序会控制错电机
- 建议用 udev 规则按设备序列号绑定固定名字（如 `/dev/ttyMOTOR_PAN`）

---

### R9 【低】`init_ui()` 与激光耦合

`init_ui()` 把"激光是否可用"当成了"UI 是否可用"的前置条件。实际上数码管/按钮和激光是两个独立的 GPIO 外设，**激光继电器坏了不该导致整个模式选择 UI 失效**。

合理做法是单独检测 `gpiozero` 是否可导入，而不是复用 `_HAVE_LASER`。

---

### R10 【低】没有自动化测试

全部功能依赖真实硬件（摄像头、云台、串口、GPIO），没有任何单元测试或 CI。

**仅有的离线验证手段**：视觉部分可以用 `my-cv-one.py` 在 PC 上跑 `sucai/*.jpg` 做回归——**修改视觉算法后建议至少跑一遍，确认图片仍能被正确识别**。

---

### R11 【低】没有 `requirements.txt`

依赖需要手动装（见 4.1）。版本也没有固定，`opencv-python` 大版本升级可能改变阈值行为。

**建议**：`pip freeze > requirements.txt`，或至少写一个带版本下限的清单。

## 8. 换机 / 移植检查清单

从一台机器搬到另一台（或从开发机搬到树莓派）时，逐项确认：

- [ ] 代码文件全部复制（`*.py`、`sucai/`、`other/`）
- [ ] **不要**复制 `__pycache__/`（不同 Python 版本的 `.pyc` 会失效，且污染仓库）
- [ ] 安装依赖：`pyserial`、`opencv-python`、`numpy`、`gpiozero`
- [ ] 修改 `SERIAL_PORT_PAN` / `SERIAL_PORT_TILT` 为**本机**的串口名
- [ ] 确认两个串口**没有接反**（接反会控制错电机，可能撞坏机构）
- [ ] 修改 `CAMERA_ID` 并核对 `CAMERA_WIDTH` / `CAMERA_HEIGHT`
- [ ] **重新标定测距**（KR1：K 值不可跨摄像头/分辨率复用）→ 跑模式 12 或 `calibrate.py`
- [ ] **重新标定零点**（模式 11）→ 物理安装角度变了，`zero_offset.json` 必须重做
- [ ] 实测 `DISTANCE_MM`（激光到画板距离）和 `TILT_OFFSET_MM`（俯仰偏移）
- [ ] 检查 `A4_BRIGHT_THRESH`（现场光照不同，通常要重调）
- [ ] 按实际场地核对模式 5/6/7 的 `draw_angle`（R3）
- [ ] 确认运行目录正确（R2：先 `cd` 到项目根）
- [ ] 戴护目镜，清场后再开激光（R4）

## 9. 常见问题

**Q：运行时报 `ModuleNotFoundError: No module named 'serial'`**
A：装 `pyserial`：`pip3 install pyserial`。注意包名是 `pyserial`，导入名才是 `serial`。

**Q：提示"未检测到数码管/按钮硬件，无法选择模式"就退出了**
A：没装 `gpiozero`、不在树莓派上、或 GPIO 权限不足。见 R5。要调视觉请用 `my-cv.py` / `my-cv-one.py`。

**Q：`ModuleNotFoundError: No module named 'gpiozero'`**
A：`pip3 install gpiozero`。PC 上装不了属正常，程序会降级为无激光模式（但因 R5 仍会退出）。

**Q：`my-cv-one.py` 打印"✗ 图片读取失败"**
A：`sucai/` 目录缺失或 `IMAGE_NAME` 指向的文件不存在。确认 `sucai/9.jpg`（或你设置的文件）在工作目录下。

**Q：找不到 A4 纸**
A：先跑模式 12 或 `my-cv.py` 看二值图。多数是 `A4_BRIGHT_THRESH` 不合适（弱光调低），或纸太远导致面积小于 `A4_MIN_AREA`。

**Q：距离显示为 0 / "未标定，不显示距离"**
A：`calibration.json` 不存在或 `K1`/`K2` 为 0。见 R1、R2。

**Q：画的图形尺寸偏大或偏小**
A：距离补偿用了错误的值。检查 R1（K 值是否匹配当前摄像头/分辨率）和 R2（是否读到了正确的标定文件）。也可用 `SHAPE_DRAW_OFFSET_MM` 微调。

**Q：两个电机转反了 / 控制错轴**
A：`/dev/ttyACM0` 和 `/dev/ttyACM1` 接反了（USB 插入顺序变化会导致）。见 R8。

**Q：改了 `my-cv-one.py` 的参数，主程序没变化**
A：`work-pi.py` 不 `import my-cv.py`，是**代码复制**关系，必须手动同步。见 3.1。

**Q：模式 12 按 Q 退出时程序报错**
A：早期版本有 `NameError`（引用了未定义的 `msg`/`ok`/`stype`/`params`），当前仓库版本**已修复**。若你看到这个错误，说明在跑旧代码。
